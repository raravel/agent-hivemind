## Description
Integrate `pack_non_conflicting` into `hv run --ready-only --limit N` and switch the JSON output shape from a bare array to `{tasks, deferred}`. The two consumers (`/hv:plan` and `/hv:task` SKILLs) are updated in T4 and T5 respectively; for this task the CLI shape is the contract — SKILL consumers come next.

## Implementation outline
- After `_find_ready_tasks` returns priority-sorted candidates, call `core/scope.pack_non_conflicting` with `limit = limit or len(candidates)`
- Map selected IDs back to `(fm, body, path)` tuples for output
- Emit JSON object: `{"tasks": [...task entries...], "deferred": [{"id", "reason", "conflict_with", "overlap"}]}`
- `text` format mode (non-JSON) is unchanged in shape but should report deferred IDs on stderr for human readers
- `--ready-only` without `--limit` still applies packing across all candidates (default behavior keeps the disjoint guarantee)
- Sequential paths (`hv run` without `--ready-only`) are unchanged

## Completion Criteria
- [ ] `hv run --ready-only --limit 3 --format json` returns `{"tasks": [...], "deferred": [...]}` with the disjoint-scope guarantee
- [ ] When given 5 fixture tasks with one wide-scope (`"*"`) at top priority, packing returns one selected (the wide-scope task) and four deferred
- [ ] When given 3 fixture tasks with pairwise-disjoint scopes, packing returns three selected and zero deferred
- [ ] Deferred entries record `conflict_with` (the selected task they collided with) and `overlap` (the matching entries)
- [ ] Empty/missing scope on a candidate forces solo behavior — that task is selected only as the first pick of its batch
- [ ] `tests/unit/test_run_parallel.py` covers: priority preservation, slot filling, deferred accuracy, wide-scope solo, empty-scope solo
- [ ] All commands in `../docs/verify.md` pass
